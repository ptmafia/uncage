このページでは、それぞれの考え方を一度ずつ説明します。このサイトでは、どのページでも用語を同じ意味で使います。1行の定義は[用語集](/docs/ja/reference/glossary/)にまとめています。

## ウェブサイトとハブ

**ウェブサイト**はあなたのウェブアプリケーションです。**ハブ**（`@uncage/hub`）は、そのバックエンドに`createHub()`でマウントするUncageの部品です。マウント先は、常駐するNodeプロセス（**従来モード**）か、サーバーレス関数（**FaaS モード**。[デプロイモードを選ぶ](/docs/ja/start/choose-deployment-mode/)を参照）です。ハブはFetchハンドラー（`hub.fetch`）であり、1つのベースパス（デフォルトは`/api/uncage`）の下で次のものを提供します：

- UIが使う**ブラウザ向けAPI**（リクエストとレスポンスの形はLocal モードのデーモンの`/v1` APIと同じなので、`@uncage/client`、`@uncage/react`、`@uncage/react-ui`はそのまま動きます）。
- コンピュータを接続するための**デバイス用エンドポイント**とインストーラー（`install.sh`、`install.ps1`）。
- 接続済みのコンピュータが`<basePath>/agent`でつないでくる**トランスポート**：**WebSocket**（従来モード。`@uncage/hub/node`の`attachWebSocket(hub, server)`で設定）と**HTTPストリーミング**（どのプラットフォームでも使えます）。ハブがこれらを提供し、エージェントがどちらかを選びます。

ウェブサイトはそれぞれ自分のハブを動かします。間にUncageのクラウドサービスは存在しません。

ウェブサイトには、コンピュータが接続するときに目にする**ID**と**名前**があります。デフォルトではどちらも`publicUrl`のホスト（`app.example.com`）から決まります。自分で決めるには`site: { id, name }`を指定します。コンピュータはIDをローカルフォルダ名に使うので、固定しておいてください。

## マシン（コンピュータ）とエージェント

**マシン**は、あなたのウェブサイトに接続された1人のユーザーのコンピュータです。UIの文言では**コンピュータ**と呼びます。ユーザーは複数台を接続できます。それぞれにID（`mch_…`）、名前、OS、エージェントのバージョン、利用できるランタイム（Claude Code、Codex）、そして**オンライン**かどうかの情報があります。

**エージェント**は、そのコンピュータ上のバックグラウンドプロセスです。`uncage setup`がユーザー単位のバックグラウンドサービス（macOSではlaunchd、Linuxではsystemd、Windowsではスケジュールされたタスク）としてインストールする`uncage agent`がこれにあたります。中国語のUIでは**守护进程**と表記されます。1つのエージェントは複数のウェブサイトに同時に接続でき、ウェブサイトごとにマシントークン、接続、ワークスペースのルートを1つずつ持ちます。

マシンは、接続が生きている間（ハートビートに応答しているWebSocket、または開いているHTTPストリームがある間）**オンライン**です。ハブは10秒ごとにpingを送り、pingに2回続けて応答しなかったマシンをオフラインとみなします。そのため、UIには約30秒以内に「offline」と表示されます。

**ペアリング**には、テレビアプリへのサインインに近いデバイスログインを使います。`uncage setup <url>`が短い**ユーザーコード**を取得し、ユーザーがウェブサイトの`/device`ページでそれを承認すると、CLIが**マシントークン**を受け取ります。トークンはコンピュータ上（`~/.uncage/agent.yaml`、モード0600）にのみ保存され、ハブはそのSHA-256ハッシュを保持します。マシンを取り消すと（ウェブサイトから、またはコンピュータ上で`uncage sites remove`を実行）、トークンは即座に無効になります。

## セッション

**セッション**は、1台のマシン上で1つのランタイムを使って行う1つの会話です。IDはマシンが決めます。ハブが返すセッションにはすべて`machineId`が含まれるので、UIはそのコンピュータの状態を表示できます。

- マシン上では、セッションごとに専用の**ワークスペース**フォルダ`~/Uncage/<site host>/<session id>/`が作られます。ブラウザがフォルダを選ぶことはできません。
- セッションの**正となるデータ**は、マシンのローカルデータベース（`~/.uncage/sites/<site id>/data`）です。
- 新しいセッションは、`machineId`で指定したコンピュータで実行されます。指定がなければ、そのユーザーのオンラインのコンピュータのうち最後に確認されたものが使われます。オンラインのコンピュータがなければ、セッションの作成は`machine_offline`で失敗します（ユーザーが一度もコンピュータを接続していない場合は`machine_not_found`）。

## 実行（Run）

**実行**は、1つのプロンプトと、それに答えるためにエージェントが行うすべての処理です。1つのセッションでアクティブにできる実行は一度に1つまでです（2つ目は`session_busy`になります）。実行の状態は次のとおりです：

| 状態 | 意味 |
| --- | --- |
| `queued`、`running` | 処理中 |
| `waiting_approval` | 承認カードで一時停止中 |
| `completed` | 正常に終了 |
| `failed` | エラーで終了 |
| `cancelled` | ユーザーが停止した（Stop） |
| `interrupted` | 実行の途中でプロセスが終了した（エージェントの再起動など） |

実行を開始するには`Idempotency-Key`ヘッダーが必要です。これにより、リクエストを再試行しても2つ目の実行が始まることはありません。`@uncage/client`が自動で設定します。

## イベント

セッションで起きることはすべて、セッションごとの**シーケンス**番号を持つ**イベント**です：`session.created`、`run.started`、`message.delta`、`tool.started`、`approval.requested`、`run.completed`などです。ブラウザはイベントを**SSE**（`GET <basePath>/sessions/:id/events`）で受け取り、切断されても最後に受け取ったシーケンス（`Last-Event-ID`）から再開できます。マシンはイベントをまずローカルデータベースに書き込むので、ネットワークが切れても実行は続きます。接続が戻ると、ブラウザは重複なく追いつきます。

## 承認とパーミッションモード

Claude Codeがコマンドの実行、ファイルの編集、または確認が必要なツールの呼び出しをしようとすると、実行が一時停止し、UIに**承認**カード（**Allow** / **Deny**、許可／拒否）が表示されます。判断はブラウザ→ハブ→マシンの順に伝わり、マシンがアトミックに決定します。2つのタブ（または2つのハブノード）が同時に応答した場合は、最初の判断が採用され、もう一方は`409`を受け取ります。保留中の承認は10分で期限切れになります。

セッションの**パーミッションモード**は、どこまで承認を求めるかを決めます：

| モード | 動作 |
| --- | --- |
| `default` | コマンドと編集の前に確認します（読み取りなど、Claude Codeが安全と判断するものは引き続き自動で許可されます） |
| `acceptEdits` | ファイルは確認なしで編集し、コマンドは引き続き確認します |
| `plan` | 計画だけを立て、何も変更しません |
| `auto` | ユーザーの判断が必要なものをランタイムが決めます |
| `bypassPermissions` | 一切確認しません。**ユーザーが自分のコンピュータで有効にした場合にのみ利用できます**（[トラストモデル](/docs/ja/concepts/trust-model/)を参照） |

## サイトツール

**サイトツール**は、Claude Codeが呼び出せる、あなたのウェブサイトの機能です。`defineTool({ name, description, input, handler, requiresConfirmation? })`で宣言します。

- マシンが受け取るのは、名前、説明、`input`のJSON Schemaだけです。Claude Codeからは`mcp__site__<name>`というツールとして見えます。
- **ハンドラーはあなたのバックエンドで実行されます**。実行されるのはそのマシンの接続を保持しているハブノードで、`ctx.user`にはセッションの所有者が設定されます。
- `requiresConfirmation: true`を指定すると、`bypassPermissions`モードであっても、すべての呼び出しの前に承認カードが表示されます。
- すべての呼び出しは検証され（セッションがこのマシンとユーザーのものであること、ツールがこの実行に提供されていること、引数が`input`に合致すること）、ハブのストアに記録されます。

ガイド：[ツールを定義する](/docs/ja/guides/define-tools/)。

## スキル

**スキル**は、指示（Markdown）と任意のテンプレートファイルからなり、`SkillSpec`（`{ name, description, markdown, files? }`）として宣言します。エージェントは実行の前に、セッションのワークスペース内の`.claude/skills/<name>/SKILL.md`にスキルを書き込みます。Claude Codeは通常のClaude Codeスキルと同じように、タスクが説明に合致したときにそれを読み込みます。スキルはデータであり、ハブが実行するコードではありません。

ガイド：[スキルを書く](/docs/ja/guides/write-skills/)。

## マニフェスト

**マニフェスト**は、1つの実行に提供されるツールとスキルの集合です。デフォルトでは、登録したすべてのツールとスキルが含まれます。`selectManifest({ user, prompt, sessionId, runtime })`を使えば実行ごとに選べます。たとえば、公開用のツールは有料プランのユーザーにだけ提供する、プロンプトが請求書に関するものなら`invoice`スキルだけを提供する、といった使い方です。ハブは各実行のツール一覧を記録し、一覧にないツールの呼び出しは`tool_failed`（`details.reason: 'not_in_manifest'`）で失敗します。ツールやスキルの変更は次の実行から反映されます。サイトツールに対応していないランタイム（Codex）にはスキルだけが渡され、セッションに`site_tools_unsupported`の警告が表示されます。

ガイド：[実行ごとにツールとスキルを選ぶ](/docs/ja/guides/select-manifest/)。

## ファイルチャネル

**ファイルチャネル**を使うと、ツールのハンドラーは、ファイル全体をJSONの引数で受け渡す代わりに、マシン上の実行のワークスペースからファイルを読み取れます：`ctx.files.pull(path)`（ファイルまたはフォルダ、合計50 MiB・1ファイル10 MiBまで）と`ctx.files.read(path)`（1ファイル）です。マシンはワークスペース外のパスを拒否し、シンボリックリンクはたどらず、フォルダ内のハードリンクされたファイルはスキップします。

ガイド：[ツールを定義する → ユーザーのコンピュータからファイルを読む](/docs/ja/guides/define-tools/#ユーザーのコンピュータからファイルを読む)。

## ストレージ

ストアは2つあります：

- **マシン上**：セッションデータ（正）。`~/.uncage/sites/<site id>/`配下のPGliteに保存されます。
- **ハブ上（`HubStore`）**：マシン、デバイスコード、セッションインデックス（どのセッションを誰が所有し、どのマシンにあるか）、実行のマニフェスト、ハブ経由でアップロードされた添付ファイル、ツール呼び出しの監査記録。FaaS モードでは、各マシンの**アウトボックス**（まだ処理されていない番号付きのコマンド）とツール呼び出しの結果も保持します。従来モードには`pgliteHubStore`（組み込み、単一プロセス、`@uncage/hub/node`から読み込み）を、複数ノードとFaaS モードには`postgresHubStore`を使います。どちらかを必ず`store`として渡します。

**セッションストレージ**（`sessionStorage`オプション）は、ハブが会話も保持するかどうかを決めます：

- `'machine'`（デフォルト）：履歴はマシンから読み込みます。マシンがオフラインの間、ユーザーは過去の会話を見られません。
- `'site'`：マシンはすべてのイベントを順番どおりにハブへ複製し、再接続後は最後に確認応答されたシーケンスから再送します。マシンの電源が切れていても、履歴はサイト上で読めます。

ガイド：[サイトストレージ](/docs/ja/guides/site-storage/)。

## クラスター

ハブは、ロードバランサーの背後で複数の**ノード**として動かせます。FaaS モードでは、関数インスタンスのそれぞれがノードです。マシンのWebSocketは1つのノードにあり、ブラウザのリクエストは別のノードに届くことがあります。**クラスターアダプター**（`ClusterAdapter`）は、どのノードがどのマシンを保持しているかを共有し、ノード間でコマンド、ウェイクアップ、イベントを運びます。`memoryCluster()`（デフォルト）は単一プロセス用、`redisCluster()`または`postgresCluster()`は複数プロセス用です。さらに、すべてのノードが1つの`HubStore`（Postgres）を共有する必要があります。

ガイド：[マルチノード](/docs/ja/guides/multi-node/)。

## ローカルポリシーとアクティビティ

最終的な決定権はユーザーのコンピュータにあります。`~/.uncage/agent.yaml`の`localPolicy.allowBypass`（デフォルトは`false`）は、`bypassPermissions`を可能にする唯一のスイッチです。また`localPolicy.allowedPermissionModes`で、どのウェブサイトでも使えるモードの上限を設定できます。ウェブサイトが引き起こしたすべてのコマンド、ツール呼び出し、ファイル取得、承認はローカルの**アクティビティログ**に書き込まれ、`uncage activity`で表示できます。

ガイド：[ローカルポリシー](/docs/ja/guides/local-policy/)。

## トラストモデル

ウェブサイトは、サインイン中のユーザーの代わりに操作することを信頼されています。ただし、その範囲にはウェブサイト側では変えられない制限があります：ウェブサイトからコードやシェルコマンドは送れない、バイパスを有効にできるのはユーザーだけ、すべての操作がローカルに記録される、の3つです。[トラストモデル](/docs/ja/concepts/trust-model/)を読んでください。

## Local モード

ここまでの内容はすべて**Connected モード**の話です。**Local モード**にはハブもペアリングもありません。`uncage serve`（**デーモン**）がアプリと同じマシンで動き、アプリは同一オリジンの**プロキシ**（`@uncage/server/proxy`の`createUncageHandler`）を通じてデーモンと通信します。プロキシは、デーモンのBearerトークンをサーバー側で付与します。セッション、実行、イベント、承認は同じように動作します。[Local モード クイックスタート](/docs/ja/start/quickstart-local/)を参照してください。
