ウェブサイトがユーザーのコンピュータで何をしてよいかは、[トラストモデル](/docs/ja/concepts/trust-model/)で説明しています。このページでは、それがどのように強制されるかを列挙します。

## 通信

プロトコルバージョンは`2`です。エージェントは常に**外向きに**接続するので、ユーザー側でポートを開ける必要はありません。ハブは一方または両方のトランスポートを提供し（`transports`オプション）、エージェントはWebSocketを使い、3回失敗するとHTTPSストリーミングに切り替えます。

- **WSS**（従来モード）：コンピュータごとに1本のWebSocket。ハブは10秒ごとにpingを送り、pingに2回応答しなかったコンピュータはオフラインと表示されます。
- **HTTPSストリーミング**（FaaSモード、およびフォールバック）：`POST <basePath>/agent/connect`でリンクを開き、`GET <basePath>/agent/stream`がNDJSONの行（1行に1つのJSONオブジェクト。シーケンス番号付きのハブのフレームと、10秒ごとの`{"ctl":"ping"}`）を返し、エージェントは`POST <basePath>/agent/events`でメッセージを送ります。すべてのリクエストは、マシントークンを`Bearer`ヘッダーで送ります。ストリームは`stream.maxDurationMs`の後に終了し、エージェントはすぐに再接続します。`cursor`を付けてストリームを開き直すと、そこまでのすべてのフレームが確認済みになるため、切れたストリームでフレームが失われることも、確認済みのフレームが繰り返されることもありません。上りのメッセージには冪等なIDが付くので、再試行が二重に適用されることはありません。
- ハブが`localhost`、`127.0.0.1`、`[::1]`（開発用）にある場合を除き、平文の`ws://` / `http://`は拒否されます。
- フレームとリクエストボディはJSONで、両側でプロトコルのスキーマに照らして検証され、それぞれ1 MiBまでです。ハブは`minAgentVersion`より古いエージェントを拒否します（WebSocket：`upgrade_required`、HTTP：`426 upgrade_required`）。
- マシントークンがない、または誤っている、HTTPの`/agent/*`へのリクエスト、WebSocketのアップグレード、`/machine/revoke`は、クライアントIPごとにレート制限されます（`rateLimits.agentAuthFailuresPerMinute`、60回）。カウントはストアで行われます。
- プレゼンス：どちらのトランスポートでも、pingの間隔の2回分（約30秒）を超えて無応答のコンピュータはオフラインと表示されます。

## マシントークン

- コンピュータとウェブサイトの組ごとに1つのトークン。32バイトのランダム値をbase64urlでエンコードしたものです。
- 保存されるのはコンピュータ上の`~/.uncage/agent.yaml`（モード0600。それより緩いパーミッションは厳しく直されます）だけです。ハブはSHA-256ハッシュを保存します。
- ログに出力されることも、イベントに含まれることも、ブラウザに送られることもありません。
- ウェブサイトから（`hub.revokeMachine`、`DELETE <basePath>/machines/:id`）も、コンピュータから（`uncage sites remove`）も取り消せます。取り消されたトークンは即座に使えなくなり、その接続は閉じられます。
- 同じコンピュータを再ペアリングすると（コンピュータはペアリング時にランダムな`machineKey`を送ります）、マシンIDはそのままでトークンがローテーションされます。古いトークンを使っている接続は閉じられます。

## デバイスログイン

- ユーザーコード：紛らわしい文字を除いた31文字のアルファベット（`ABCDEFGHJKMNPQRSTUVWXYZ23456789`）から選ばれる8文字。有効期間は10分で、1回限りです。
- コードを承認できるのは、サインイン中のユーザーが`/device`ページから行う場合だけです。このページはフレーム内での表示とCSRFから保護する必要があります（[ガイド](/docs/ja/guides/auth-and-device-approval/#承認ページdevice)）。
- レート制限：クライアントIPごとに1分あたり20個のデバイスコード、ユーザーごとに10分あたり10回のコード照会または判定の失敗。カウントはハブのストアで行われ、すべてのノードと関数インスタンスで共有されます。
- デバイスコード（CLIのポーリング用シークレット）とユーザーコードは、ハッシュ化して保存されます。

## ユーザー間の分離

- すべてのブラウザリクエストは`getUser(req)`で認証されます。
- すべてのセッション、実行、承認、添付ファイル、コンピュータ（machine）は、**所有者と組み合わせて**検索されます。他のユーザーのIDには`404`が返り、存在しない場合と区別できません。
- コンピュータがイベントを報告できるのは自分のセッションについてだけで、ツールを呼び出せるのは、自分のユーザーのセッションでハブを通じて開始された実行についてだけです。
- 別のオリジンからの状態を変更するブラウザリクエストは`403 forbidden_origin`になります。

## ツールの実行

- ツールハンドラーは**あなたのサーバーで**実行されます。コンピュータが受け取るのは、名前、説明、JSON Schemaだけです。
- ツール名には`__`を含められず、コンピュータ上では名前空間が付く（`mcp__site__<name>`）ため、Claude Codeの組み込みツールを覆い隠すことはありません。
- 引数は、ハンドラーの実行前にzodスキーマで検証されます。
- 呼び出しが受け付けられるのは、実行のマニフェストにあるツールだけです。各呼び出しは監査記録としてハブのストアに保存されます。
- `requiresConfirmation`のツールは、すべてのパーミッションモードで、呼び出しのたびにユーザーに確認します。
- タイムアウト（120秒）、同時実行数の上限（コンピュータあたり8）、結果のサイズの上限（1 MiB弱）で処理量が制限されます。

## ファイルチャネル

- パスは相対パスで、セッションのワークスペースの内側でなければなりません。コンピュータは`realpath`でパスを解決し、外側のものはすべて拒否します。
- シンボリックリンクがたどられることはありません。ハードリンクされたファイルは、フォルダの取得ではスキップされ、単一ファイルの場合は拒否されます。
- 1回の取得あたり最大50 MiB、1ファイルあたり最大10 MiBです。取得はオール・オア・ナッシングです（一部だけ渡されることはありません）。

## ユーザーのコンピュータ上

- 各セッションは専用のフォルダ`~/Uncage/<site host>/<session id>/`（モード0700）で実行され、既存のプロジェクトの中で実行されることはありません。ブラウザがフォルダを選ぶことはできません。
- スキルはそのフォルダの`.claude/skills/<name>/`の内側にだけ、シンボリックリンクをたどらずに書き込まれます。
- `bypassPermissions`には、コンピュータ上で`localPolicy.allowBypass: true`が必要です。`localPolicy.allowedPermissionModes`で使えるモードを制限できます。
- ウェブサイトが行ったことはすべて`~/.uncage/sites/<site id>/activity.log`（秘匿化済み）に記録されます。
- `install.sh`の内容は固定です。npmから`@uncage/cli`をインストールするだけで、それ以外は何もしません。

## ACPエージェント

[その他のACPエージェント](/docs/ja/guides/use-any-acp-agent/)は、ユーザーのコンピュータ上でローカルプロセスとして、それぞれ独自のログインで動きます。ユーザーを守るルールは次のとおりです。

- **同意は起動仕様の全体に結び付きます。** `npx`や`uvx`で配布されるエージェントはコードをダウンロードするため、`uncage runtimes enable <id>`を実行した後にだけ動きます。同意には、ランナー、パッケージ（バージョンは問わない）、引数、環境変数が記録されます。レジストリが後で別のものを実行するようになった場合、そのエージェントは再度の`enable`を待ちます。
- **レジストリの信頼ルール。** ACPレジストリのエージェントが有効になるのは、このコンピュータにインストールされていて、ACPのハンドシェイクに応答した場合だけです。レジストリの更新でコマンドが変わると、再度有効にするまで外されます。`autoDetect: false`で検出を無効にでき、`disable`は他の設定にかかわらずそのエージェントを止めます。
- **プロジェクトの設定ファイルは同意を与えられません。** Localモードでは、`uncage.config.yaml`の`enable`と`consented`は無視されます。
- **プロジェクトの設定ファイルの`agents[].command`は、同意なしで実行されます。** プロジェクトの`uncage.config.yaml`には任意のコマンドを書け、`uncage serve`がそれを起動します。`uncage doctor`と`uncage serve`は起動時にそのようなコマンドをすべて表示します。信頼できるプロジェクトでだけ実行してください。
- **「常に許可」は選びません。** ACPのパーミッション要求に対して、Uncageはエージェントの`allow_once`または`reject_once`の選択肢で答え、`allow_always`や`reject_always`は決して選びません。エージェントがセッションの外に保存する可能性があるためです。
- **サイトツールはループバックのMCPサーバー経由です。** Runごとに`127.0.0.1`でMCPサーバーが立ち上がり、1回限りのBearerトークンとともに`mcpServers`でエージェントに渡されます。`requiresConfirmation`のツールは、呼び出しのたびにUncageで確認します。ハンドラーは引き続きあなたのサーバーで動きます。
- **スキル**はセッションのフォルダの`.uncage/skills/<name>/`の内側にだけ書き出され、最初のプロンプトで一覧にされます。
- レジストリのダウンロード（`cdn.agentclientprotocol.com`、最大で1日1回。`UNCAGE_ACP_REGISTRY_REFRESH=0`で無効化）が提供するのは名前、コマンド、アイコンだけで、それ自体は何も実行しません。

## Local モード

デーモンはループバックにだけバインドし、`~/.uncage/token`（モード600）のBearerトークンを要求し、外部の`Origin`を拒否します。ブラウザがデーモンにアクセスできるのは同一オリジンのプロキシを通じてだけで、プロキシは`Host`（DNSリバインディング対策）と`Origin`をチェックします。詳細は[Local モードの詳細](/docs/ja/reference/local-mode/#セキュリティモデルlocal-モード)を参照してください。

## ウェブサイト開発者向けチェックリスト

- [ ] `getUser`が実際にサインインしているユーザー、または`null`を返す。セッションCookieが`Secure`で、`SameSite=Lax`または`Strict`である。
- [ ] `publicUrl`が`https://`のオリジンであり、プロキシが元の`Host`を転送している。
- [ ] `/device`がサインインを必須とし、`frame-ancestors 'none'`と`X-Frame-Options: DENY`を送り、CSRF対策済みのPOSTで判定している。
- [ ]すべてのツールハンドラーが、読み書きの範囲を`ctx.user.id`に限定している。
- [ ]ツールのエラーがユーザーに見せても安全な内容で、詳細はログに出している。
- [ ]公開、送信、支払い、削除を行うツールが`requiresConfirmation: true`を使っている。
- [ ]コンピュータから取得したファイルを信頼できないものとして扱っている（サンドボックスで配信し、必要に応じてスキャンする）。
- [ ]プロキシの背後で、レート制限のためのクライアントIPが設定されている。
- [ ]独自のPostgresプールやRedisクライアントを使う場合、`'error'`リスナーを付けている。
