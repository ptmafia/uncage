ウェブサイトがユーザーのコンピュータで何をしてよいかは、[信頼モデル](/docs/ja/concepts/trust-model/)で説明しています。このページでは、それがどのように強制されるかを列挙します。

## 通信

- エージェントは **WSS** でハブに**外向きに**接続します。ハブが `localhost`、`127.0.0.1`、`[::1]`（開発用）にある場合を除き、平文の `ws://` / `http://` は拒否されます。ユーザー側でポートを開ける必要はありません。
- フレームは JSON で、両側でプロトコルのスキーマに照らして検証され、各 1 MiB までです。プロトコルバージョンは `1` で、ハブは `minAgentVersion` より古いエージェントを `upgrade_required` で拒否します。
- ハブは 10 秒ごとに ping を送ります。ping に 2 回応答しなかったコンピュータはオフラインと表示されます。

## machine トークン

- コンピュータとウェブサイトの組ごとに 1 つのトークン。32 バイトのランダム値を base64url でエンコードしたものです。
- 保存されるのはコンピュータ上の `~/.uncage/agent.yaml`（モード 0600。それより緩いパーミッションは厳しく直されます）だけです。ハブは SHA-256 ハッシュを保存します。
- ログに出力されることも、イベントに含まれることも、ブラウザに送られることもありません。
- ウェブサイトから（`hub.revokeMachine`、`DELETE <basePath>/machines/:id`）も、コンピュータから（`uncage sites remove`）も取り消せます。取り消されたトークンは即座に使えなくなり、その接続は閉じられます。
- 同じコンピュータを再ペアリングすると（コンピュータはペアリング時にランダムな `machineKey` を送ります）、machine ID はそのままでトークンがローテーションされます。古いトークンを使っている接続は閉じられます。

## デバイスログイン

- ユーザーコード：紛らわしい文字を除いた 31 文字のアルファベット（`ABCDEFGHJKMNPQRSTUVWXYZ23456789`）から選ばれる 8 文字。有効期間は 10 分で、1 回限りです。
- コードを承認できるのは、サインイン中のユーザーが `/device` ページから行う場合だけです。このページはフレーム内での表示と CSRF から保護する必要があります（[ガイド](/docs/ja/guides/auth-and-device-approval/#承認ページdevice)）。
- レート制限：クライアント IP ごとに 1 分あたり 20 個のデバイスコード、ユーザーごとに 10 分あたり 10 回のコード照会または判定の失敗。ハブのノードごとにカウントされます。
- デバイスコード（CLI のポーリング用シークレット）とユーザーコードは、ハッシュ化して保存されます。

## ユーザー間の分離

- すべてのブラウザリクエストは `getUser(req)` で認証されます。
- すべてのセッション、実行、承認、添付ファイル、コンピュータ（machine）は、**所有者と組み合わせて**検索されます。他のユーザーの ID には `404` が返り、存在しない場合と区別できません。
- コンピュータがイベントを報告できるのは自分のセッションについてだけで、ツールを呼び出せるのは、自分のユーザーのセッションでハブを通じて開始された実行についてだけです。
- 別のオリジンからの状態を変更するブラウザリクエストは `403 forbidden_origin` になります。

## ツールの実行

- ツールハンドラーは**あなたのサーバーで**実行されます。コンピュータが受け取るのは、名前、説明、JSON Schema だけです。
- ツール名には `__` を含められず、コンピュータ上では名前空間が付く（`mcp__site__<name>`）ため、Claude Code の組み込みツールを覆い隠すことはありません。
- 引数は、ハンドラーの実行前に zod スキーマで検証されます。
- 呼び出しが受け付けられるのは、実行のマニフェストにあるツールだけです。各呼び出しはハブのストアで監査記録されます。
- `requiresConfirmation` のツールは、すべてのパーミッションモードで、呼び出しのたびにユーザーに確認します。
- タイムアウト（120 秒）、同時実行数の上限（コンピュータあたり 8）、結果のサイズの上限（1 MiB 弱）で処理量が制限されます。

## ファイルチャネル

- パスは相対パスで、セッションのワークスペースの内側でなければなりません。コンピュータは `realpath` でパスを解決し、外側のものはすべて拒否します。
- シンボリックリンクがたどられることはありません。ハードリンクされたファイルは、フォルダーの取得ではスキップされ、単一ファイルの場合は拒否されます。
- 1 回の取得あたり最大 50 MiB、1 ファイルあたり最大 10 MiB です。取得は全部か無かです。

## ユーザーのコンピュータ上

- 各セッションは専用のフォルダー `~/Uncage/<site host>/<session id>/`（モード 0700）で実行され、既存のプロジェクトの中で実行されることはありません。ブラウザがフォルダーを選ぶことはできません。
- スキルはそのフォルダーの `.claude/skills/<name>/` の内側にだけ、シンボリックリンクをたどらずに書き込まれます。
- `bypassPermissions` には、コンピュータ上で `localPolicy.allowBypass: true` が必要です。`localPolicy.allowedPermissionModes` で使えるモードを制限できます。
- ウェブサイトが行ったことはすべて `~/.uncage/sites/<site id>/activity.log`（秘匿化済み）に記録されます。
- `install.sh` の内容は固定です。npm から `@uncage/cli` をインストールするだけで、それ以外は何もしません。

## Local モード

デーモンはループバックにだけバインドし、`~/.uncage/token`（モード 600）の Bearer トークンを要求し、外部の `Origin` を拒否します。ブラウザがデーモンにアクセスできるのは同一オリジンのプロキシを通じてだけで、プロキシは `Host`（DNS リバインディング対策）と `Origin` をチェックします。詳細は [Local モードの詳細](/docs/ja/reference/local-mode/#セキュリティモデルlocal-モード)を参照してください。

## ウェブサイト開発者向けチェックリスト

- [ ] `getUser` が実際にサインインしているユーザー、または `null` を返す。セッション Cookie が `Secure` で、`SameSite=Lax` または `Strict` である。
- [ ] `publicUrl` が `https://` のオリジンであり、プロキシが元の `Host` を転送している。
- [ ] `/device` がサインインを必須とし、`frame-ancestors 'none'` と `X-Frame-Options: DENY` を送り、CSRF 対策済みの POST で判定している。
- [ ] すべてのツールハンドラーが、読み書きの範囲を `ctx.user.id` に限定している。
- [ ] ツールのエラーがユーザーに見せても安全な内容で、詳細はログに出している。
- [ ] 公開、送信、支払い、削除を行うツールが `requiresConfirmation: true` を使っている。
- [ ] コンピュータから取得したファイルを信頼できないものとして扱っている（サンドボックスで配信し、必要に応じてスキャンする）。
- [ ] プロキシの背後で、レート制限のためのクライアント IP が設定されている。
- [ ] 独自の Postgres プールや Redis クライアントを使う場合、`'error'` リスナーを付けている。
