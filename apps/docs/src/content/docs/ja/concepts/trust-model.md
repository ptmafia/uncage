Connected モードでは、ウェブサイトがユーザー自身のコンピュータ上で作業を開始できます。そのためには「ウェブサイトに何ができるのか」に明確に答える必要があります。その答えがこのページです。

## 要点

- **ウェブサイトは、サインイン中のユーザーの代わりに操作することを信頼されています**。ユーザーがあなたのウェブサイトで行うこと（実行の開始、カードの承認、そのユーザーとしてのツールの呼び出し）は、ユーザー自身の操作とみなされます。
- **ただし、ウェブサイトが変えられない制限の範囲内に限られます**。これらの制限はハブではなく、ユーザーのコンピュータ上でエージェントが強制します：

| 保証 | 仕組み |
| --- | --- |
| ウェブサイトからコードやシェルコマンドは送られない | ハブが送るのはデータだけです：ツールの名前・説明・JSON Schema、スキルのテキストとテンプレートファイル、そして固定リストにあるコマンド（セッションの作成、実行の開始、キャンセル、判断、設定の更新、添付ファイルの追加、スナップショット／セッション／イベントの読み取り）。ツールの**ハンドラー**はあなたのサーバーで実行され、ユーザーのコンピュータで実行されることはありません。 |
| `bypassPermissions`を有効にできるのはユーザーだけ | そのコンピュータの`~/.uncage/agent.yaml`に`localPolicy.allowBypass: true`が設定されていない限り、エージェントはこのモードを`policy_denied`で拒否します。ハブのどのオプションでもこれは変えられません。 |
| ローカルでの上限設定（任意） | `localPolicy.allowedPermissionModes`で、このコンピュータ上でウェブサイトが使えるモードを制限できます。 |
| 確認付きツールは必ず確認する | `requiresConfirmation: true`のサイトツールは、`bypassPermissions`モードであっても、呼び出しのたびに承認カードを表示します。 |
| ローカルにすべてを記録 | すべてのコマンド、サイトツールの呼び出し、ファイル取得、承認は`~/.uncage/sites/<site id>/activity.log`に追記されます。`uncage activity`で表示できます。 |
| 隔離されたフォルダ | 各セッションは専用のフォルダ`~/Uncage/<site host>/<session id>/`で実行され、ユーザーの既存のプロジェクト内で実行されることはありません。そのフォルダ外からのファイル取得は拒否され、シンボリックリンクはたどられません。 |
| ユーザーはいつでも切断できる | `uncage sites remove <id>`はウェブサイト上でコンピュータを取り消し、ローカルのトークンを削除します。`uncage agent uninstall`はエージェントを停止します。 |

## ウェブサイトができること

- ユーザーが接続したコンピュータ上で、そのユーザーとして、コンピュータが許可するパーミッションモードでセッションと実行を開始する。
- ユーザーに承認カードを表示し、ユーザーの判断を受け取る。
- サイトツールとスキルを提供する。ツールをいつ呼び出すかはClaude Codeが決め、呼び出されるとあなたのサーバーでハンドラーが実行されます。
- ツールのハンドラー内から、ファイルチャネルを通じて**セッション専用のフォルダから**ファイルを読み取る。
- 会話のレプリカを自分のストレージに保持する（`sessionStorage: 'site'`）。
- 自分の側からコンピュータを取り消す（`hub.revokeMachine`、またはUIのマシン一覧から）。

## ウェブサイトができないこと

- セッションフォルダ内でのClaude Code（またはCodex）自体の実行以外に、ユーザーのコンピュータで何かを実行する。
- `bypassPermissions`を有効にする、またはコンピュータの`allowedPermissionModes`にないモードを使う。
- セッションをディスク上のどこで実行するかを選ぶ。Connected モードではブラウザからの`workspace`フィールドは無視され、フォルダはエージェントが作成します。
- 他のユーザーのコンピュータやセッションにアクセスする。ブラウザからのリクエストはすべて`getUser(req)`と照合され、他のユーザーのセッションやマシンに対しては、存在しない場合とまったく同じく`404`が返ります。
- マシントークンを見る。ハブが保存するのはハッシュだけで、トークンがログに出力されたりイベントに含まれたりすることはありません。
- ユーザーのClaudeログインを読み取る。Claude Codeはそのコンピュータ上の自身の認証情報を使います。

## ユーザーが知っておくべきこと

コンピュータを接続することで、ユーザーは次のトレードオフを受け入れることになります：

- **Claude Codeは、セッションフォルダとそのパーミッションモードの範囲内で、ユーザー自身のアカウントを使って動作します**。`default`モードでは、コマンドと編集はユーザーが承認します。ただしClaude Code自体が、ファイルの読み取りなど安全と判断した一部の操作を自動で許可します。それらもツールステップとして表示されます。
- **ユーザーが承認したコマンドは、ユーザーの権限で実行されます**。これは通常のClaude Codeのコマンドと同じです。承認カードにはコマンドやパスが表示されるので、必ず読んでください。
- **ウェブサイトは会話を見ることができます**（会話をルーティングし、保存することもあります）。ただし、Claude Codeが会話に読み込んだ場合や、ツールがセッションフォルダから取得した場合を除き、コンピュータ上の他のファイルは見えません。

## ウェブサイト開発者の責任

Uncageは、自分のユーザーの信頼を悪用するウェブサイトから守ることはできません。ただし、信頼に値するサイトにするための部品は提供します：

- **すべてのリクエストを認証する**。`getUser(req)`は、実際にサインインしているユーザーか`null`を返す必要があります。[認証とデバイスの承認](/docs/ja/guides/auth-and-device-approval/)を参照してください。
- **`/device`を保護する**。コードを承認すると、コンピュータがアカウントに紐付けられます。サインイン中のユーザーにだけ提供し、フレームへの埋め込みを拒否し、CSRF対策をしたPOSTで判断を受け付けてください。
- **ツールのハンドラーで所有権を確認する**。`ctx.user`はセッションの所有者です。すべての検索に使ってください（`WHERE owner = ctx.user.id`）。
- **ユーザーに見せても安全なエラーを投げる**。ハンドラーが投げたメッセージは、ユーザーとモデルに表示されます。
- **`requiresConfirmation`を使う**。公開、送信、支払い、削除を行うツールには必ず指定してください。

通信、トークン、制限については[セキュリティ](/docs/ja/reference/security/)も参照してください。
