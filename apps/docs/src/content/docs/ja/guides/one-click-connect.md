ユーザーはUncageのエージェントを1回インストールするだけです。以後、Uncageを組み込んだどのサイトも、ターミナルをもう一度開かなくても使えます。サイトがリンクを表示し、ユーザーがクリックし、自分のコンピュータで確認し、いつもどおりサイトで承認します。

:::note[ステータス]
macOS、Linux、Windowsでビルドしてユニットテスト済みです。実際のハンドラーを登録するテストは、macOS、Linux、WindowsのCIランナーで実行されます（使い捨てのスキームと一時ホームを使用）。ユーザー自身のコンピュータでのワンクリック、実際のダイアログ、実ブラウザでのダッシュボード：実機での確認待ちです。
:::

## 仕組み

1. `uncage setup`（または`uncage agent install`）が、バックグラウンドのエージェントをインストールし、**さらに**`uncage://`リンクのハンドラーをOSに登録します。`uncage agent uninstall`で削除されます。
   - **macOS：** ユーザー単位の小さなアプリ`~/Library/Application Support/Uncage/UncageConnect.app`を、LaunchServicesに登録します。管理者権限は不要です。
   - **Linux：** `~/.local/share/applications/uncage-connect.desktop`と、`x-scheme-handler/uncage`に対する`xdg-mime default`。`xdg-mime`がない場合は、注記を表示してスキップします。
   - **Windows：** `HKCU\Software\Classes\uncage`（現在のユーザーのみ）。
2. あなたのサイトが**このコンピュータですでにUncageを使っていますか？ ワンクリックで接続**を表示します。`<ConnectMachine>`パネルが`uncage://connect?url=<あなたのサイト>`へリンクします（ハブの[`installInfo.connectUrl`](/docs/ja/reference/http-api/)。モバイルでは非表示）。ページからはハンドラーがあるかどうかを判別できないため、インストールコマンドが引き続き主な手順です。
3. OSが`uncage connect <リンク>`を実行します。リンクを検証し、**ネイティブ確認**を表示し、「接続」が押されて初めて通常のデバイスフローを開始します。ブラウザでサイトの`/device`ページが開き、ユーザーが承認をクリックします。
4. 新しいサイトが`~/.uncage/agent.yaml`に保存され、バックグラウンドのエージェントが再起動します。

手動でも実行できます：`uncage connect https://app.example.com`。[CLIリファレンス](/docs/ja/reference/cli/)を参照してください。

ワンクリック接続には`@uncage/cli` 0.4以降が必要です。既存の0.3では、`npm i -g @uncage/cli@latest`を実行し、`uncage agent install`（または`uncage setup`）をもう一度実行して初めてハンドラーが登録されます。登録はそこでしか行われないためです。

## 受け付けるもの

`uncage connect`は、パラメータが**ちょうど1つ**の`uncage://connect?url=<サイト>`、または単なるURLを受け付けます。ほかの処理より前に、次のいずれかに当てはまるサイトURLは拒否します。

- `https://`ではない（プレーンな`http://`は`localhost`、`127.0.0.1`、`[::1]`のみ）、
- ユーザー名やパスワード、クエリ、フラグメントを含む、
- 空白や制御文字を含む、または2048文字より長い、
- 別のスキーム（`javascript:`、`data:`、`file:`）、または`uncage://`の別のアクションやパラメータ。

## 確認と、サイトの身元確認

ペアリングの前に、このコンピュータ上のダイアログが尋ねます。**このコンピュータを`example.com`に接続しますか？** まずサイトの**登録可能ドメイン**（Public Suffix Listに基づき、`vercel.app`のようなプライベートサフィックスも含むため、そこでは各プロジェクトが別々の所有者として扱われます）、次にハブの完全なURL、そして接続によって何が可能になるか（サイトの運営者が、いつでもこのコンピュータでコーディングエージェントのセッションを開始でき、そのツール承認の確認にもローカルポリシーの範囲内で答えられること。信頼できるサイトだけに接続してください）を表示します。**既定はキャンセルです。** ダイアログはシステムの言語（英語、中国語、日本語）で表示されます。

次のそれぞれについて、警告の行が追加されます。

| 警告 | 条件 |
| --- | --- |
| 国際化文字 | ホストがIDNの場合。punycode形式が表示されます。 |
| IPアドレスそのもの | サイトがドメインではなくIPの場合。 |
| 特定のページ | パスがルートでも既定の`/api/uncage`でもない場合。共有オリジンでは、パスがドメインの所有者とは別の人のものである可能性があります。 |
| 初回 | このコンピュータが、その登録可能ドメインに接続したことがない場合。 |
| ほかのサイトに似ている | ラベルが、接続済みドメインと紛らわしい文字の骨格（数字、キリル文字、ギリシャ文字をラテン文字に対応づけ、`rn`≒`m`など）で同じ、または編集距離が2以内の場合。 |

OSごとの確認方法です。

| OS | ダイアログ |
| --- | --- |
| macOS | `/usr/bin/osascript`（アラート。10分間応答がなければ「いいえ」として扱います） |
| Windows | OKとキャンセルのあるメッセージボックス（`WScript.Shell`のPopup、既定はキャンセル）。システム標準のWindows PowerShell経由で表示します |
| Linux | `zenity`（優先）、なければ`kdialog`（ディスプレイ環境、つまり`DISPLAY`または`WAYLAND_DISPLAY`がある場合） |

ダイアログツールがない、またはダイアログを表示できず（グラフィカルセッションがない）、コマンドがターミナルで実行されている場合は、ターミナルで`Connect? [y/N]`と尋ねます。ダイアログもターミナルもない場合は、拒否して手動での実行方法を表示します。**ダイアログがなければ接続はしません。** そのほか：

- 同時に尋ねる質問は1つだけです。リンクを繰り返し発火させるページがあっても、ダイアログは重なりません。
- ユーザーが確認した後、ハブが示す承認ページは確認済みのオリジン上にあり、応答するサイトも確認済みのURLでなければなりません。そうでなければ何も保存されません。
- サイトが自己申告した名前は、ドメインなしでは表示されません。
- 終了コード：`0`は接続済み、`1`はキャンセルまたは拒否、`2`はリンクが不正。
- どのプロンプトも（ターミナルのものも含め）、10分間応答がなければ「いいえ」として扱います。
- ユーザーがキャンセルした後、同じサイトについては30秒間、再び尋ねません。
- リンクから起動された場合（登録されたハンドラーは`uncage connect --from-link`を使います）、結果（接続できたか、できなければその理由）がネイティブの通知として表示されます。Windowsではこの実行は非表示で行われるため、コンソールウィンドウは現れません。

## ローカルダッシュボード

`uncage dashboard`は、このコンピュータの接続済みサイトのページを開きます。

- 各サイトの名前とドメイン、マシンID、接続日時、状態（オンライン、オフライン、失効）とトランスポート、提供しているランタイム、直近の（マスク済みの）アクティビティ。
- **切断**：サイト側のマシントークンを失効させ（`uncage sites remove`と同様）、エージェントを再起動します。
- ACPエージェントのオン／オフ（`uncage runtimes enable|disable`と同じ同意の扱い）と、ローカルポリシーの読み取り専用ビュー。

`127.0.0.1`のランダムなポートで動くページです。リンクのフラグメント（`#…`。ブラウザはサーバーに送りません）に使い捨てのトークンが含まれます。ページはそれを1度だけAPIトークンに交換して`sessionStorage`に保存し、アドレスバーからフラグメントを取り除きます。Cookieは使いません。すべてのリクエストに、正しい`Host`（`127.0.0.1:<ポート>`。DNSリバインディングを防ぎます）、別の`Origin`がないこと、そしてヘッダーのAPIトークンが必要で、満たさなければ`403`になります。CORSヘッダーは付きません。ページを閉じるか、30分間リクエストがないと終了します（`--no-browser`はブラウザを開かずリンクを表示します）。ページはシステムの言語に従います。

## 脅威モデル

ワンクリックはフィッシングを安上がりにします。どんなウェブページでも`uncage://connect?url=https://evil.example`を発火できるからです。これが黙って成功すると、自分のサイトでサインイン済みの攻撃者が、被害者のコンピュータを**攻撃者の**アカウントに承認し、そこからユーザーのコーディングエージェントを操作できてしまいます。これを防ぐのは次のものです。

- **ネイティブ確認**は、ウェブページの外で誰が要求しているのかを示し、既定は「いいえ」です。ウェブページがこれをクリックすることはできません。
- **身元の警告**が、類似ドメイン、IDN、IPホスト、初めてのサイトを目立たせます。
- **悪意のあるサイトに対して、デバイスフローは何も守りません。** サイトは自分の`/device`ページを制御しており、自分の側で承認できます。**ネイティブ確認が唯一の関門**なので、信頼できるサイトだけを確認してください。（正直なサイトでは、デバイスフローが引き続きコードを照合し、コンピュータを表示します。）
- **中央のレジストリはありません。** Uncageはどのサイトも保証しません。ダイアログが示すのはリンクが言っていることの事実で、判定ではありません。ユーザーは、自分が始めた接続だけを確認してください。
- 接続済みのサイトがコンピュータ上でできることは変わりません。[トラストモデル](/docs/ja/concepts/trust-model/)、[ローカルポリシー](/docs/ja/guides/local-policy/)、ツールごとの承認が引き続き適用されます。ダッシュボードですべての接続を確認し、失効できます。

[セキュリティ](/docs/ja/reference/security/)も参照してください。
