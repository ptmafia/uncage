# Uncage V0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A pnpm monorepo that lets a developer embed real Claude Code (and, mock-verified, Codex) into a web app: one local service with Sessions / Runs / Events / Approvals over HTTP + SSE, a React SDK with Kumi-styled default UI and headless hooks, and a CLI (`uncage doctor` / `uncage serve`).

**Architecture:** `@uncage/core` is an embeddable Node SDK (session/run/event/approval orchestration over a PGlite store) that drives `RuntimeAdapter`s. `@uncage/server` wraps core in Fastify (REST + SSE, token + Origin + Host checks) and ships a same-origin proxy (`createUncageHandler`) for Next.js. Browser side: `@uncage/client` (transport) → `@uncage/react` (store + `applyEvent` reducer + hooks) → `@uncage/react-ui` (default components).

**Tech Stack:** Node ≥22 (dev on 24), pnpm 10 workspaces, Turborepo 2, TypeScript 5 (ESM only), tsup 9, Zod 4, Fastify 5, PGlite 0.5 + Drizzle ORM 0.45, Pino 10, Vitest 5, Playwright 1.65, React 19, Next.js 16, react-markdown + remark-gfm, lucide-react, `@anthropic-ai/claude-agent-sdk` 0.3.318 (Claude Code CLI 2.1.318 on dev box).

**Spec:** `docs/superpowers/specs/2026-11-06-uncage-v0-design.md` (read it first; it overrides) plus `docs/02-PRD.md`, `docs/03-ARCHITECTURE.md`, `docs/04-ENGINEERING.md`.

## Global Constraints

- macOS is the supported platform. `engines.node` is `">=22"`. All packages are ESM-only (`"type": "module"`).
- The server binds to `127.0.0.1` only, with default port `4783`. Every `/v1/*` route requires `Authorization: Bearer <token>`. A request carrying an `Origin` header not in `security.allowedOrigins` gets 403, and that list is empty by default. A `Host` header other than `127.0.0.1:<port>` / `localhost:<port>` gets 403.
- The token lives in `~/.uncage/token`, mode `0600`, and is never logged, never put in events, and never sent to the browser.
- The data dir defaults to `~/.uncage/data` (PGlite). Event retention defaults to 7 days. Approval TTL defaults to `600_000` ms.
- Zero-config `allowedRoots` is `[process.cwd()]` at serve time. Workspace paths are `realpath`'d before the check.
- At most one active Run per Session (`session_busy`, HTTP 409).
- Never expose or set `bypassPermissions`. The Claude adapter uses `permissionMode: 'default'`.
- Never build shell strings from prompts. Child processes use `spawn`/`execFile` with arg arrays.
- No telemetry. Logs (Pino) redact `authorization`, `token`, `*.apiKey`, and env values, and never log prompt text at info level.
- The error body is `{ error: { code, message, hint?, retryable, details?, requestId } }`. Every `ErrorCode` has a human `message` and a `hint`.
- UI CSS: plain CSS with `--uncage-*` variables and `uc-` class prefix, shipped as `@uncage/react-ui/styles.css`. Icons come from `lucide-react`. `locale` is `'en' | 'zh-CN'`, default `'en'`. The examples use `'zh-CN'`.
- Kumi is a visual reference only. Re-implement it and copy no Kumi source files.
- Codex protocol facts that are unverified against a real binary (approval response envelope `{"id":…,"result":{"decision":…}}`, item payload field names) live only in `packages/runtime-codex/src/protocol.ts` and are marked `// UNVERIFIED`.

## Review Focus

1. **A multi-byte UTF-8 character (CJK/emoji) split across two SSE network chunks** must render intact. The client SSE parser has to decode with `TextDecoder` in `stream: true` mode. Test: Task 9.
2. **When the server restarts while an approval is pending,** after a reload the run must show `interrupted` and the approval `expired` with disabled buttons. Nothing should stay stuck in "submitting". Test: Task 5.
3. **Model output containing `<script>` / `<img onerror>` / `javascript:` links** must render as inert text, with no XSS. That means react-markdown without `rehype-raw`, and `urlTransform` dropping `javascript:`. Test: Task 11.
4. **If the runtime process dies mid-run** (Claude CLI killed, Codex process exit), the run must become `interrupted` within 5 s, pending approvals become `cancelled`, and the SSE stream must keep working. Test: Task 8 (fake codex `crash` scenario) and Task 7.
5. **A workspace path that is a symlink pointing outside `allowedRoots`** must be rejected with `invalid_workspace`. Test: Task 4.

Behaviour (the source of each rule is in brackets):
- **Run lifecycle** [docs/04 §2]: `startRun` persists `queued` + `run.started`, then drives `adapter.run()` in the background. Events are translated into envelopes: `message.delta` gets `chunkIndex` per messageId, and `native.session` updates `sessions.native_session_ref` (no event). It moves to `running`, then to `waiting_approval` while any approval is pending, then terminal. A second `startRun` while active throws `session_busy`. The same idempotencyKey returns the same Run.
- **Approval bridge** [docs/03 §7]: `ctx.requestApproval` creates the ApprovalRequest (`state: pending`, `version: 1`, `expiresAt = now + ttl`, `allowedScopes: ['once']`), emits `approval.requested`, and returns a promise held in an in-memory `Map<approvalId, resolver>`.
- **`decide`**:
  1. Validate that `scope === 'once'` (otherwise `unsupported_capability`).
  2. Check idempotency: the same key and the same decision returns the stored result; the same key with a different decision throws `approval_already_resolved`.
  3. CAS `pending → submitting`. Losing the race throws `approval_already_resolved`, and an expired approval throws `approval_expired`.
  4. Resolve the in-memory promise. If no resolver exists, set the state to `expired` and throw `approval_expired`.
  5. CAS to `approved`/`denied` and emit `approval.resolved`.
- **TTL**: a timer per approval. On expiry it CASes `pending → expired`, emits `approval.updated`, and resolves `{decision:'expired'}`.
- **Cancel**: `runs.cancel` aborts the adapter signal, sets pending approvals to `cancelled` (resolving `{decision:'cancelled'}`), and waits ≤5 s for the iterator to end. The final state is `cancelled` and `run.cancelled` is emitted. Cancelling a run that has already finished is a no-op and returns the run unchanged (idempotent).
- **Adapter failure**: if the iterator throws or ends without a terminal event, the run becomes `interrupted` (`run.interrupted`, reason `runtime_disconnected`) and its pending approvals become `cancelled`.
- **Startup reconciliation** [docs/03 §10]: on `createUncage`, every run in `queued|running|waiting_approval` becomes `interrupted` with `run.interrupted` reason `server_restart`, and every `pending|submitting` approval becomes `expired` with `approval.updated`.
- **Resume/read-only**: if a session has `nativeSessionRef` and its adapter's `capabilities().nativeResume` is false, set `readOnly: true`. `startRun` on a read-only session throws `session_read_only`, whose hint is "Start a new session".
- **`events({after})`**: if `after < minRetainedSequence - 1`, the first yielded item is a thrown `event_replay_unavailable`. Live delivery uses an in-process emitter after the store commit (append → commit → publish).

  - `run.started` adds a user MessageView (id `user_<runId>`) and a timeline item.
  - Consecutive `tool.*` events within a run collapse into one `tools` timeline item, which is closed by the next message or approval.
  - `message.delta` appends text only when `chunkIndex` equals the next expected index; an out-of-order index is buffered until the gap fills.
  - `approval.resolved` does not change the tool status.
  - A `409 approval_already_resolved` on `decide` is treated as success; the store refetches the snapshot.
- Hooks use `useSyncExternalStore` with memoized selectors.
