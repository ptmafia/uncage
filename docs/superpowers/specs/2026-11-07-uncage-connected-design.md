# Uncage 0.2 — Connected Mode（网站指挥用户本地 CC）设计

> 2026-11-07 · 前置：V0（本地嵌入）与 Composer 已发布为 `@uncage/*@0.1.x`，代码在 `github.com/ptmafia/uncage`。
> 本文定义新版本方向；与旧文档冲突时以本文为准。

## 1. 意图

“只给本地应用构建 CC 环境意义不大。”用户真正要的是：**终端用户不离开网站，就能指挥自己电脑上的 Claude Code，CC 干活时调用网站的能力，产出的过程和资产都留在网站上。**

参照物：Multica 的“添加机器”——网站给一条 `curl … | bash`，再 `xxx setup`，浏览器登录后守护进程常驻并主动连回网站，网站自动识别“机器上线”。

参照场景（Kumi）：用户在网站上新建自定义应用 → 网站把“自定义应用规范”和任务下发到用户本地 CC → CC 在本地写代码、构建 → CC 调用网站的资产能力创建资产、走正常发布流程 → 网站上同时看到过程和产出的资产。

**Uncage 要做的是让“这件事”对任何网站都变简单的通用框架**：封装不变的部分，变化的部分开放扩展。Kumi 是将来的第一个接入方，但本版本先用框架自带的参考 demo 网站证明通用性。

## 2. 目标

1. **接入极简**：网站展示两条命令（安装 + `setup`），用户执行后浏览器确认登录，机器与该用户在网站上的账号绑定，网站实时显示在线。
2. **网站内指挥**：在网站里发任务、看流式过程、点审批、停止，体验与现有 `<AgentChat>` 一致；执行发生在用户本机 CC。
3. **网站能力注入**：网站开发者声明“能力（工具）”和“技能（规范/模板）”；用户的机器连上后自动拿到，CC 以该用户身份调用网站接口，结果写回网站。
4. **开放扩展**：工具、技能、本地扩展（钩子/动作）、会话存储、鉴权、运行时，都有清晰的扩展点与类型。
5. **参考 demo**：仓库内一个可运行的参考网站，端到端跑通“一句话 → 本地 CC 生成 → 调网站工具发布成资产 → 网站展示资产与过程”。
6. **帮助站**：同时面向开发者与 coding agent，足够友好（见 §8）。

## 3. 非目标 / 反目标

- 不做云端托管 CC（CC 只在终端用户自己的机器上跑）。
- 不共享任何人的 Claude 登录；每台机器用其主人的 CC 登录。
- 不做网站开发者之间的多租户平台（每个网站自托管自己的 hub）。
- **反目标**：网站能借此在用户机器上静默执行任意操作（必须有用户可见的会话、权限模式与审批）；用户为接入需要做内网穿透或公网暴露端口；扩展需要改框架源码。

## 4. 架构

```text
终端用户浏览器 ──(同源)──► 网站（开发者自己的应用）
                              ├─ 网站原有后端 / 账号体系
                              └─ @uncage/hub（挂进网站后端）
                                    · 机器注册与配对（device login）
                                    · 机器长连接（WebSocket，机器主动连入）
                                    · 路由：网站 UI ⇄ 用户的机器
                                    · 能力/技能注册表 → 下发给机器
                                    · 工具调用回调：以该用户身份执行网站能力
                                    · 可选：会话存储在网站侧
                                         ▲  wss（出站，无需公网 IP）
用户电脑 ── uncage agent（守护进程，launchd 常驻）────┘
              · 现有 core：sessions/runs/events/approvals/attachments
              · 运行时适配器：Claude Code / Codex
              · 把网站下发的能力以 MCP 工具形式注入每次 CC 会话
              · 本地扩展（钩子/动作）
              · 默认本地存储（PGlite）
```

- **复用**：`protocol`、`core`、两个运行时适配器、`client`/`react`/`react-ui` 全部沿用；新增传输层与 hub/agent 两端。
- **保留旧模式**：V0 的“本机代理”（Local Mode）继续可用，Connected Mode 是新增模式；两者共享同一套协议与 UI。

### 4.1 接入流程（不变部分，框架封装）

1. 网站页面显示：`curl -fsSL https://<网站>/uncage/install.sh | bash` 与 `uncage setup https://<网站>`（URL 由 hub 生成，品牌化在网站域名下）。
2. 安装脚本：检查 macOS / Node ≥22 / Claude Code；安装 `@uncage/cli`（全局）；不满足时打印可复制的修复命令。
3. `uncage setup <url>`：发起 device login（类 OAuth Device Authorization：机器拿到短码与验证链接 → 打开浏览器 → 用户在网站已登录态下确认 → 机器获得**机器令牌**，绑定该用户与该机器）。无浏览器场景显示短码手动输入。
4. 安装 launchd 守护进程并启动；守护进程用机器令牌主动连 hub（wss），断线指数退避重连。
5. 网站页面通过 hub 实时看到“机器已上线”（含机器名、CC 版本/登录状态）。
6. 用户可在网站或本机 `uncage logout` / `uncage machines revoke` 吊销。

### 4.2 运行流程

网站 UI（`@uncage/react-ui` / hooks）→ 网站同源路由 → hub → 用户机器的 agent → core → CC。事件按现有序号/重放语义回传 hub → UI。审批卡、停止、附件、模型/权限设置全部保持现有语义。机器离线时 UI 明确显示离线、不可发送。

### 4.3 网站能力注入

- 开发者在网站后端用 hub SDK 注册：
  - **工具**：名称、描述、JSON Schema 参数、`handler(args, ctx)`（`ctx.user` 为该会话所属用户、`ctx.session`、`ctx.attachments` 等）、`requiresConfirmation?`（为 true 时在网站 UI 弹确认卡后才执行）。
  - **技能**：Markdown 说明 + 可选模板文件（例如“自定义应用规范”），按名称或按任务类型下发。
- 机器连上后 hub 下发能力清单；agent 为每次 CC 会话注入一个 MCP server（工具调用经长连接回到 hub → 执行 handler → 返回结果）；技能写入会话工作目录或作为系统提示/skill 提供给 CC。
- 工具调用全部以会话所属用户的身份鉴权，hub 侧二次校验；所有调用进入事件流，在网站可见。

### 4.4 扩展点（变化部分）

| 扩展点 | 默认 | 开发者可替换为 |
|---|---|---|
| 网站工具 / 技能 | 无 | 任意数量，类型化注册 |
| 本地扩展（钩子、动作，运行在用户机器） | 无 | 以 npm 包或网站下发的声明式配置提供，如 `onRunCompleted` → 部署 |
| 会话存储 | 用户本地 PGlite | 网站侧（hub 存储适配器：开发者自己的数据库）或其他存储；公开 `Store` 接口 |
| 鉴权 | — | 适配网站现有登录（hub 提供 `getUser(request)` 钩子） |
| 运行时 | Claude Code、Codex | 实现 `RuntimeAdapter` |
| UI | `<AgentChat>`（Kumi 风格） | props / slots / headless hooks |

**注意（我方判断，已向用户说明）**：会话仅存本地时，机器离线则网站看不到历史；需要“网站上始终可见过程”的接入方应把会话存储配置为网站侧。参考 demo 默认演示网站侧存储，框架默认仍为本地。

## 5. 参考 demo（仓库内）

一个最小网站（我方判断：Next.js + 简单账号 + SQLite/PGlite），功能：登录 → “连接我的电脑”（两条命令 + 在线状态）→ 对话框发需求（如“做一个介绍我们产品的落地页”）→ 本地 CC 生成静态页面 → 调用网站工具 `create_asset` / `publish_asset` 上传并发布 → 网站“资产”页列出并可预览已发布页面，旁边可回看生成过程。端到端用真实 Claude Code 验证（Playwright + 系统 Chrome）。

## 6. 安全底线（框架封装，不可绕过）

- 机器令牌：每机器一枚、可吊销、只存本机 0600 文件、不出现在日志/事件中。
- hub ⇄ agent 仅 wss；hub 校验机器令牌与用户绑定；agent 只接受来自已配对 hub 的指令。
- 网站无法绕过本机权限模式：默认每次询问；`bypassPermissions` 仍需**本机**显式开启（网站无法远程开启）。
- 工作目录围栏沿用；每个会话使用 agent 管理的专属工作目录（默认 `~/Uncage/<site>/<session>`），不默认指向用户已有项目。
- 网站工具 `requiresConfirmation` 的确认发生在网站 UI；所有工具调用写入事件流。
- 安装脚本：从网站域名提供，内容固定、可审阅，不执行网站动态下发的任意 shell。

## 7.1 信任模型（用户确认）

默认信任网站：用户在网站上的操作即代表本人。框架强制两条底线：`bypassPermissions` 只能在用户本机显式开启，网站无法远程开启；本机记录完整操作日志（`uncage activity` 可查看）。另外提供可选的本机权限上限（`uncage.config.yaml` 中限定网站可用的权限模式），用户想收紧时使用。

## 8. 帮助站（我方判断，可调整）

- 位置：仓库 `apps/docs`，静态站，部署到 GitHub Pages 或同类（发布前确认）。
- 面向开发者：5 分钟上手（Connected Mode 与 Local Mode 两条路）、概念讲解（机器/会话/运行/能力/技能/扩展）、每个扩展点的指南与完整示例、API 参考（由 TypeScript 类型生成）、安全模型、排错。
- 面向 coding agent：每页提供纯 Markdown 版本；站点根提供 `llms.txt` 与 `llms-full.txt`；提供一份可直接交给 Claude Code/Codex 的“接入 Uncage”技能（SKILL.md）与复制即用的提示词；示例代码全部可运行并在 CI 中编译校验；术语与 API 名称在全站一致。
- 中英双语（我方判断：英文为主，关键页中文）。

## 10. 审阅后补充的裁定（我方判断，已列给用户）

1. **会话数据以机器本地为准**：agent 始终以本机 PGlite 为真实来源（运行不依赖网络往返）。配置“网站侧存储”时，agent 按事件序号把只追加的事件异步复制到 hub；断线重连后从 hub 已确认的最后序号补传。只有 agent 写事件，不存在冲突。审批决定由网站发给 agent，在本机完成原子判定后再复制回去。附件：网站上传的文件经 hub 送到机器本地保存，元数据复制到网站；文件本体是否镜像到网站由存储适配器决定。
2. **hub 的运行方式**：hub 是一个长驻的 Node 服务。可以挂进网站已有的 Node 后端（Express/Fastify/Next 自定义服务器），也可以作为独立进程 `uncage hub` 和网站并排运行，通过回调 / 签名令牌对接网站账号。**必须支持多节点部署（用户确认）**：机器可能连在节点 A，浏览器请求打到节点 B。hub 通过可插拔的「集群适配器」完成在线状态共享和跨节点消息路由，默认是单进程内存实现，官方再提供 Redis 实现（发布订阅 + 在线表）；会话与事件的网站侧存储同样走适配器（多节点时必须用共享存储，比如开发者自己的 Postgres）。参考 demo 和 E2E 要覆盖“两个 hub 节点 + Redis”的场景。Serverless（如 Vercel 函数）不能直接托管 hub，文档给出“网站在 Vercel、hub 单独部署”的做法。
3. **文件通道是框架内置能力**：工具 handler 通过 `ctx.files` 从会话工作目录按需拉取文件或目录（由 agent 打包上传，有大小上限，进度和结果进入事件流），不需要把整站文件塞进 JSON 参数。
4. **本地扩展只来自本机安装**：会执行代码的扩展只能来自用户本机安装的 npm 包或用户自己写的本地配置。网站只能下发声明式数据（技能文本、模板、工具清单），永远不能下发要在本机执行的代码或 shell。
5. **多网站、多机器**：一个守护进程可以同时连接多个网站，每个网站一个令牌、一条连接、一个工作目录根（`~/Uncage/<site>/`）。一个用户可以接入多台机器，新会话默认用最近在线的那台，可在界面上切换。Connected Mode 与 Local Mode 的 `uncage serve` 可以在同一台机器上共存。
6. **技能和工具按会话决定**：网站在创建会话时，通过钩子按任务类型选出这次要用的技能和工具，随会话一起下发。修改后从下一个会话开始生效，不热更新正在运行的会话。
7. **版本兼容**：握手时协商协议版本；hub 声明最低 agent 版本，低于这个版本时 agent 自动升级（npm）后再重连；hub 同时兼容当前版本和上一个次版本。
